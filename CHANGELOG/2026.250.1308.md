# 2026.250.1308 — ci: assert packaged charly systemd units + /etc/charly config in install-test

## Summary

Extend the install-test to assert the charly package's new systemd units + system-wide config (shipped since v2026.250.0854):

- unit files exist: `/usr/lib/systemd/system/charly-mcp.service` and `/usr/lib/systemd/user/charly-mcp.service`
- non-autostarting: `systemctl is-enabled charly-mcp` must report `disabled` (a container without a systemd manager reports the absent-manager error, which is accepted); when `systemctl` is absent the [Install] `WantedBy=` section is asserted plus the absence of any enable marker (`multi-user.target.wants` symlink), so a post-install `systemctl enable` can never slip through
- `/etc/charly/charly.yml` exists and `charly box validate -C /etc/charly` exits 0
- the MCP server starts on demand: the test container runs no systemd, so `charly mcp serve --listen 127.0.0.1:18765` (foreground, `timeout 5`, cwd=`/etc/charly`) must stay up until the timeout (exit 124)
